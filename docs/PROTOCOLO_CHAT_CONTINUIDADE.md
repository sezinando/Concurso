# Protocolo de Continuidade entre Chats

## Antes de responder "o que estudar hoje"

O chat deve consultar o estado compartilhado do projeto e:

1. identificar a versão do registrador;
2. localizar revisões vencidas;
3. localizar retestes;
4. localizar erros recorrentes;
5. localizar unidades estudadas sem evidência suficiente;
6. localizar conteúdo novo elegível;
7. selecionar questões compatíveis com a unidade;
8. montar a sessão.

## Depois da sessão

O chat deve registrar somente fatos observados:

- estudo realizado;
- recuperação;
- questões respondidas;
- respostas;
- confiança;
- erros;
- correções;
- reteste;
- próximo agendamento.

## Se o chat não tiver acesso de escrita

Ele deve fornecer um bloco de evento estruturado para posterior registro, sem inventar que o GitHub foi atualizado.

## Regra de continuidade

O estado do repositório tem precedência sobre memória informal de um chat quando houver conflito.

## Regra de segurança

Nenhuma pontuação deve ser registrada apenas porque um QTI foi gerado ou disponibilizado.
